Stage 1 nutrition/serving work is authorized only in Development. Later dietary,
generation reliability, image and internal-error repairs require separate approval.
No Production changes, publishing, GitHub pushes/merges or migrations are authorized.

**Why:** The user prioritized ingredient-backed nutrition and explicitly separated
later repairs from this approval.

**How to apply:** Reuse the existing USDA/conversion infrastructure. Never replace
unknown nutrition with invented macros or zero, and do not infer frying absorption.

Event-specific dietary/cuisine selections are removed from the roadmap. Preserve
global profile personalization; do not add dietary/cuisine dropdowns to Gatherings
or Getaways.

**Why:** The user confirmed Vegan and Japanese global settings were reflected
successfully in both features and said additional selectors are unnecessary.

**How to apply:** Keep the existing profile workflow unchanged. Future event UI
changes require an explicit new request.
