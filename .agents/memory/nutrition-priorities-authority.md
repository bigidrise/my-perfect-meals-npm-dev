---
name: Nutrition Priorities authority
description: Durable ownership, semantic, and migration rules for optional food inclusion priorities.
---

Nutrition Priorities belong to the exact authoritative food subject: adult, household profile, or child. They are optional inclusion guidance, never quotas, prescriptions, treatment, required ingredients, or a replacement for nutrition targets. Adult values never flow to children, and one child's values never flow to another child. Adult customer editing uses one registry-driven multi-select shared by active onboarding and Edit Profile; it persists through the dedicated adult API, not the general profile payload. Pediatric presentation and generation use only concepts whose registry projection is explicitly approved.

**Why:** The approved foundation must preserve subject isolation and existing safety authority while allowing selected culinary preferences to invalidate Human Food Context identity. A separate selections table was rejected in favor of versioned JSONB on authoritative subject rows. UI filtering alone cannot prevent a deferred pediatric concept or stale child draft from crossing an authority boundary.

**How to apply:** Resolve and fingerprint the validated subject document in Human Food Context, keep prompt projection bounded and subordinate to safety/diet/protocol/nutrition rules, and do not reuse the Performance DemandProfile field. Customer UI renders only active registry records and uses registry education fields without invented claims. Empty selection is valid. Adult saves replace the complete versioned document and refresh exact-account caches. Child writes, reads, HFC, and prompt projection all enforce pediatric approval; child editor drafts and query keys are scoped to the exact actor-plus-child identity and reset synchronously on a subject switch. Development may run the additive migration before readiness; Production DDL runs only through the explicit release-migration gate, while ordinary Production startup fails closed on missing columns.
