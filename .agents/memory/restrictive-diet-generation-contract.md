---
name: Restrictive-diet generation contract
description: Product rule for generating varied food choices under overlapping dietary constraints.
---

Generation must receive the same authoritative dietary and protocol contract that final validation enforces. Personalization defines the available culinary universe; diversity explores only within that universe.

**Why:** A restrictive identity can make generation fail when the model sees only a label while validators apply complete rules. More profile information should improve compliant generation, not increase generic failures.

**How to apply:** Reuse canonical prompt and validation machinery, retain valid governed candidates while repairing missing positions, and vary compliant dimensions without weakening any safety or dietary rule.
