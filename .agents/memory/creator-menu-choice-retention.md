---
name: Creator Menu choice retention
description: Product rule for retaining Create a Dish and Craving Creator Menu ideas after a finished recipe appears.
---

Completing one Creator Menu idea must not consume or hide the other ideas. Keep the three-choice working set accessible with the finished meal card, following the original Creators' pattern of retaining unchosen options. The finished meal can be saved to Favorites before the user switches to another idea; generating another set or removing the current set is an explicit user action.

**Why:** Users need a chance to inspect all three options after one full recipe is made and save the completed recipes they want. Selecting an idea is not consent to discard the rest.

**How to apply:** Preserve the server-authorized concept set during normal recipe completion and page restoration. Do not override food-safety/context invalidation or treat an uncompleted idea as a saveable recipe.

For Create a Dish, a failed restoration or selection conflict is not permission
to erase saved restoration choices. Explain the failure and allow an explicit
retry; unavailable choices must remain unusable until the server verifies them.
Do not automatically regenerate a replacement set.

Create a Dish persistence must match the established Craving Creator experience.
The founder wants the persistence behavior fixed, not a one-off recovery of an
old Menu; they can create a new set themselves.

**Why:** The founder reiterated that choices had reliably persisted for months
and objected to their disappearance and the newly introduced retry warning.

**How to apply:** Finishing one recipe, normal navigation, refreshing, or a
recalculated context marker must not discard the working set. A changed marker
revokes its old authorization, not ownership of its ideas: recheck the exact
server-owned concepts against current protections before reauthorizing them.
Genuine food conflicts remain blocked and final recipes still require current
validation. Never let a late restoration overwrite an explicitly newer Menu.

**Why:** The founder reported choices disappearing after dashboard navigation
and approved a narrowly scoped recovery correction without changes to unrelated
features or safety rules.

**How to apply:** Keep recovery distinct from authorization. Preserve the saved
request through temporary failures, but never use it to bypass current food
protections or claim that an unavailable server set has been restored.
