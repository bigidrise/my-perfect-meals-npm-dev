The registry is not a complete current content inventory. Newer explanations and the hydration records need bounded reconciliation before anyone claims all clinical presentation text is covered. 3. Smallest reusable presentation structure

  1. Ordinary interface: connect the shared panel’s controls and unprotected generic headings through the existing useConsumerCopy / EN/ES resources. Examples: panel title, Info, Open source, Visit {{title}}, loading and unavailable states, and Scope. Resolve existing protected registration before treating any heading as ordinary. Localize custom entry controls at their existing caller without replacing the caller’s component.
  2. Stable display identity: add a stable resourceId to embedded cards and a stable section ID to headings when implementation is approved. Continue using hydration’s existing record.key. IDs must not depend on array order, current title text or URL alone; repeated citations can have different contextual descriptions.
  3. Keep authoritative metadata: retain source titles, author/institution names, journal citations, PMIDs, publication dates and original URLs exactly. Optionally show an approved Spanish display title above the original citation; never replace the original citation with the Spanish display title.
  4. Approved display overlay: associate each stable ID with optional displayTitle and displayDescription translation keys in the existing locale resources. Use the existing clinical review manifest for protected fields. This is a presentation-key mapping, not a second source-of-truth reference catalog or a new translation service. Embedded canonical metadata can stay in place; no wholesale extraction or database migration is necessary.
  5. Fail closed on approval: display Spanish protected copy only when the exact wording and current English source have qualified approval through the existing controlled process. Unapproved, missing or stale fields fall back independently to their existing English source. Pending candidate prose stays outside runtime translation resources. Ensure validation covers every new overlay key regardless of namespace, without weakening any existing gate.
  6. One renderer: SourceItem resolves approved display fields while retaining its exact original href, target and rel behavior. Hydration’s details/summary renderer uses the same presentation-resolution contract but preserves its existing expansion behavior, authentication, Development gate and API response. Do not send locale changes to the evidence API or mutate the records.

The overlay can cover hundreds of entries without adding a Spanish-only page. Existing explicit English, explicit Spanish and Auto preference resolution remain authoritative; no new selector, locale detection or storage is needed.

4. What requires qualified review

  • All 121 contextual card descriptions, including their claims about what a study supports.
  • Optional Spanish display titles that describe a condition, intervention or clinical claim; original official titles remain unchanged.
  • Clinical section headings and existing protected headings, including Alpha-gal, GLP-1, lab/biomarker, oncology, thyroid, pregnancy, pediatric and protocol-priority content.
  • Clinical introductions, “Drives:” explanations, ingredient restrictions, hard-block versus verify-source language, symptom/escalation guidance, medication guidance and numerical nutrient or safety explanations.
  • The protocol-priority tier labels and details, physician-precedence explanations and the concluding wellness/allergen/oncology/pregnancy/pediatric disclaimer.
  • Hydration’s ruleSupported and populationScope prose and its numeric-policy/no-number explanation. Do not translate evidence classifications as clinical conclusions without a reviewed mapping.

“Clinical Background,” “Authoritative Guidance” and other registered terms must retain their existing protected status. Generic controls can be translated independently; this does not make the clinical panel fully Spanish.

5. External sources and safety boundary

Links must continue to use their original destinations. No guessed /es URLs, automatic browser translation, external language redirects or promise that the destination is Spanish. A neutral local explanation can tell users that external sites control their language options and browser translation is their choice.

No clinical protocol, allergy restriction, nutrient rule, physician authority, reference record or reference status needs to change. Localized display content explains existing evidence; it must never become input to clinical decisions.

6. Verification recommended for an approved implementation

  • Focused EN/ES and Auto tests of actual shared renderers and caller triggers.
  • Exact metadata/link preservation, including original citations, PMIDs, institution names, href, target and rel.
  • Per-field missing, pending, stale-source and approved overlay cases; English fallback without exposing candidate Spanish prose.
  • Hydration loading/error/success fixtures with no live API or database writes, preserving its Development-only visibility.
  • Desktop/mobile sheet scrolling, long titles, detail expansion, keyboard focus, close controls and external-link accessible names.
  • Existing localization guard, client/server compilation, safety typecheck and exact approved release fingerprint. No fingerprint refreshes or suppressed diagnostics.
