# Application-wide localization inventory — founder review

## Decision

This is a completed read-only inventory, not authorization to translate more of the application.

The application has connected EN/ES interfaces alongside source-confirmed English paths, protected wording, server-owned messages and states that remain unverified. A centralized engine does not translate arbitrary page, modal or notification content. There is no defensible application-wide completion percentage.

The founder-approved 32-section consumer explanation/disclaimer remains the only wording approval carried forward here. All 32 English/Spanish resource pairs exactly match the retained approved comparison. This equality check is not new clinical/legal certification, a new browser test or permission to publish.

No application, dictionary, prompt, calculation, clinical policy, language preference, consent behavior, account, database, release baseline or review manifest was changed. No live account/API/provider operation, email, paid generation, publication, merge or Production action was performed. The pre-existing mockup-generated-file modification was left alone.

The server/delivery review is representative, not an all-endpoint/all-template census. These unknowns prevent a whole-application localization percentage.

## Classification and ownership rules

1. connected / connected-plural: exact key or bounded helper connection with values; retain the connection. Plural bases may correctly have no direct leaf.
2. hardcoded-path: manually traced English render or notification producer in current source. "Confirmed" here means confirmed source path, not a newly observed live customer incident.
3. caller-content: shared container forwards content; it does not own unique caller prose and is not a separate translation defect.
4. candidate / mixed: source configuration or partial feature evidence without enough meaning/visibility proof to call every candidate a defect.
5. missing-fallback: a reviewed call lacks resource values and uses English defaultValue or can display a raw key. Gating and fallback semantics are recorded separately.
6. missing-english-value: English absent, Spanish present; do not count as an untranslated-Spanish defect.
7. protected / approved-protected-connected: clinical/legal text requiring appropriate review; the approved onboarding pairs are a bounded positive exception, not an exemption for remaining required gates.
8. authored-data / historical-data: user, clinician, creator, provider, model or delivered historical content. Do not silently translate canonical data or rewrite history.
9. server-message / server-message-protected / delivery-template: API or email/push producers need their own presentation/error contract. Client wrappers cannot safely translate arbitrary server details.
10. technical-non-target / gated-unverified: CSS/machine material and unproven legacy/demo/gated surfaces are not customer defect totals.

All findings retain uncertainty. A null EN/ES field means no directly resolved string at that key, NOT permission to invent one. For plural findings, inspect pluralForms. For unconnected literals, the source excerpt is the English-path evidence; there is no connected Spanish value on that path, even if a similar phrase exists elsewhere in the catalog.

Important checked false positives:

- MfaSetupSection, CoachCornerCard and NutritionPersonalizationSummaryCard import useConsumerCopy as useTranslation. Treating that alias as the ordinary legacy helper creates false missing-key findings.
- shopping:smartCart.brandsSummary, athletePicker.summaryText, athletePicker.hiddenCount and mealReminders.iosScheduleConfirmed have EN/ES one/other variants. Meal reminders also have Spanish many. These four calls are not missing-base-key defects; full live count/device behavior is unverified.
- JoinStudio's joinStudio.anotherAddress has Spanish "otra dirección" but lacks English. This is an English fallback risk, not a Spanish gap.
- MealGenerationProgress's @media block is CSS, not interface copy.
- Product/feature names, enums, IDs, cuisine/allergen keys, credentials, QR/setup values, backup codes, quantities and URLs are not automatically translation targets.
- Retired ProCareTraining source has a missing key but /procare-training currently selects LegacyProCareTrainingRedirect. Do not count that old page as a demonstrated current customer screen.

## Safety and final verification boundary

Evidence generation parses source, reads JSON and uses existing pure resource modules in an allowlisted isolated context. It does not import React app startup, database clients, API route registration, accounts, billing SDKs or provider configuration. No secrets were read.

Before delivery, the report is checked for valid CSV/JSON joins, exact source anchors/hashes, source/catalog stability and self-contained static HTML. A temporary report-only static server may render inventory.html for presentation inspection; it exposes only this documentation directory, has no app boot/API bridge and is stopped afterward. This is report presentation verification, not a new application/browser-coverage claim.

Application builds, failing legacy localization/type gates, full browser journeys and workflows are intentionally not rerun/restarted for this documentation-only inventory. No application code changed and starting the main runtime could touch shared Neon. Existing limitations are preserved instead of hidden by a new synthetic completion claim.
